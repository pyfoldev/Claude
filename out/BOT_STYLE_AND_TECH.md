# Chat Helper — стиль и техническая часть
Бриф для создания бота из той же линейки, но для бизнеса (Telegram).

---

## 1. Идея и характер

**Chat Helper** — помощник, а не «система». Он живой, быстрый и немногословный. Он не читает лекций: отвечает одной-двумя строками, показывает главное, остальное прячет за кнопкой.

Принципы:
1. **Коротко.** Любой ответ влезает в экран телефона. Длинное — сворачивается в цитату (`<blockquote expandable>`) или идёт страницами.
2. **Понятно без инструкции.** Команды — обычными русскими словами, без слэшей: `бан @ник`, `стата`, `баланс`. Слэш-команды только `/start`, `/menu`, `/help`.
3. **Спокойный тон.** Без канцелярита и без «ВНИМАНИЕ!». Ошибка — одна строка: что не так и что делать.
4. **Ничего лишнего в чате.** Личные ответы (кулдауны, «нет прав», баланс) видит только автор (ephemeral) или они удаляются сами. Публично — только то, что важно всем.
5. **Безопасность по умолчанию.** Опасное действие — всегда с подтверждением (красная кнопка). Права проверяются на сервере при каждом шаге.
6. **Прозрачность.** Бот говорит, что помнит о человеке, и даёт кнопку «забудь». Внешним сервисам (ИИ) отправляется только то, о чём честно сказано в настройках.

### Голос бота (примеры)
| Ситуация | Так | Не так |
|---|---|---|
| Успех | `✅ Готово.` / `✅ Запомнил.` | «Операция успешно выполнена» |
| Ошибка | `❌ Не хватает монет. Баланс: 40` | «Произошла ошибка. Обратитесь…» |
| Нет прав | `⚠️ Нужен ранг 2.` | «У вас недостаточно привилегий» |
| Подсказка | `<i>Удалить: забудь 1</i>` | абзац пояснений |
| Лимит | `Подождите 12 с. С Premium — без ожидания.` | «Превышен лимит запросов» |

Персонаж (необязательно): имя собственное («Нори»), два стиля ответа ИИ — «по-свойски» и «вежливо» — переключаются в настройках. Для бизнес-бота лучше сделать только вежливый и тёплый стиль.

## 2. Визуальный язык

**Сообщение = эмодзи + жирный заголовок + (курсивом) одна строка пояснения + данные.**
```
🛡 <b>Модерация</b>
<i>Ответом на сообщение или с @ником.</i>
<code>бан</code> · <code>мут 30м</code> · <code>варн</code>
```
- Команды в тексте — в `<code>`: нажатие копирует.
- Статусы: ✅ успех, ⚠️ внимание, ❌ ошибка. Значения — жирным, подписи — обычным.
- Шкалы вместо чисел там, где важна доля: `2/3 ▰▰▱`.
- Списки — настоящие **таблицы** (rich-сообщения Bot API 10.1) с откатом на моноширинный текст.
- Имена людей — кликабельные ссылки (по `@нику`, если он есть, иначе `tg://user?id=`), рядом `@ник`.
- Премиум-эмодзи через единую функцию `emoji(name)` с обычным запасным символом — работает у всех.

**Кнопки**
- Меню — сетка **по 2 в ряд**, короткие подписи с эмодзи: `🛡 Модерация`, `📊 Статистика`. Не вертикальный список.
- Цвета (Bot API 9.4): `success` — включено/подтвердить, `danger` — опасное, `primary` — выбранное/главное действие. Остальное — без цвета.
- Переключатель: `✅ Капча` / `❌ Капча` (без слов «вкл/выкл»). Выбор варианта: ряд кнопок, активная — `• Текст` и синяя.
- Всегда есть `⬅️ Назад` и `⬅️ В меню`. Одно сообщение редактируется на месте, чат не засоряется.
- Опасное: сначала «Вы уверены?» с красной кнопкой и кнопкой «Отмена»; запрос живёт ~2 минут.

**Анимации и «живость»**
- Ответ ИИ в личке «печатается» (`sendMessageDraft`), в группах — индикатор «печатает…».
- Реакции вместо слов «принято», где можно.
- Подсказки команд — inline-режим: `@бот запрос`.

## 3. Структура взаимодействия
1. **Главное меню** `меню` — 8 разделов в сетке. Каждый раздел — короткий экран с примерами команд.
2. **Настройки** — разделы по 2 в ряд → внутри переключатели. Те же настройки открываются **мини-приложением** (веб-панель) одной кнопкой.
3. **Онбординг**: `/start` в личке → 3 шага и кнопки «Добавить в чат», «Веб-панель», «Меню». При добавлении в чат — мастер первой настройки (проверка прав + основные переключатели).
4. **Роли и права**: ранги 1–5 + «доступ команд» (какой минимальный ранг нужен каждой команде). Владелец бота — отдельная панель.
5. **Панель владельца**: статус, чаты, все пользователи (постранично + поиск), блок-лист, рассылка, флаги функций, бэкап, журнал, диагностика.

## 4. Техническая часть

**Стек**: Python 3.12, aiogram 3.x (Bot API 10.x), aiohttp (веб-часть), SQLite (aiosqlite) **или** PostgreSQL (asyncpg) — один код, адаптер переводит SQL-диалект; uvloop; Docker Compose; Caddy (HTTPS, заголовки безопасности, лимит тела).

**Архитектура**
- `bot/main.py` — сборка: конфиг из `.env`, БД, ИИ-клиент, middleware, роутеры, веб-сервер, фоновые задачи, polling **или** webhook.
- `bot/handlers/*` — по роутеру на область (модерация, ранги, статистика, игры, настройки, меню, капча, ИИ, опросы, память, inline…). Каждая группа команд выключается переключателем (`Enabled("mod_on")`).
- `bot/middlewares/*` — по порядку: метрики → блок-лист/обслуживание → трекер пользователей → счётчик сообщений → защита (антиспам, 18+) → память чата.
- `bot/db.py` — один класс `Database`: схема, миграции «ALTER if missing», кэши с TTL (`settings`, `rank`, `access`), **очередь записи** (счётчики и участники пишутся пачкой раз в ~5 с; чтение сначала сбрасывает очередь).
- `bot/ux.py` — новые возможности API одним местом (ephemeral, реакции, теги, таблицы) с автоматическим откатом.
- `bot/style.py` — единый стиль текстов; `bot/keyboards.py` — клавиатуры.
- `bot/panel_server.py`, `captcha_server.py` — Mini App: подпись `initData` (HMAC), свежесть, права на сервере на каждый запрос, rate-limit, CSP.
- Webhook: секретный заголовок + **постоянная очередь обновлений в БД** (подтверждаем Telegram только после сохранения), N воркеров.

**Принципы надёжности**
- Бот **запоминает каждого**, кого видел (по id, ники — опционально), из любого типа обновления; команда по id работает сразу.
- Любая внешняя вещь (ИИ, rich-таблица, ephemeral, теги) — «по возможности»: при отказе тихий откат на простое поведение.
- Суточные лимиты и кулдауны на всё платное/внешнее; возврат лимита при сбое.
- Ошибки в учёте не ломают обработку (`try/except` вокруг трекера).

**Безопасность**
- Подпись webhook обязательна (≥16 символов), `hmac.compare_digest`.
- SQL только параметризованный; имена полей — из белых списков.
- HTML-экранирование всех пользовательских строк.
- Скачивание файлов — только белый список доменов, без «универсальных» загрузчиков.
- Регулярки пользователей — проверка на катастрофический откат.
- Контейнер: `cap_drop ALL`, `no-new-privileges`; Caddy: HSTS, nosniff, лимит тела 1 МБ.
- Секреты — только в `.env`, не в репозитории.

**Монетизация**: подписка Premium за Telegram Stars (`XTR`), тарифы определяют лимиты ИИ, длину ответов, выбор модели.

## 5. Как превратить это в БИЗНЕС-бота (той же линейки)

**Сохранить**: характер и тон, визуальный язык, сетку меню, роли/права, панель владельца, мини-приложение, онбординг, очередь записи, безопасность, PostgreSQL.

**Заменить «чат-модерацию» на «работу с клиентами»**

| Chat Helper | Бизнес-бот |
|---|---|
| Участник чата | Клиент (карточка: имя, контакты, теги, история) |
| Ранги 1–5 | Роли: владелец, менеджер, оператор, бухгалтер |
| Модерация, варны | Заявки, статусы, SLA, эскалация |
| Игры, монеты, репутация | Бонусы, баллы лояльности, промокоды, рефералы |
| Капча | Проверка телефона/e-mail, защита от спама в формах |
| Статистика сообщений | Воронка: обращения → заявки → оплаты → повторные |
| «Общий сбор», рассылка владельца | Сегментированные рассылки по тегам и по событиям |
| Приветствие | Автоворонка новых клиентов, «первое касание» |

**Модули, с которых стоит начать**
1. **Каталог и заказ**: мини-приложение-витрина, корзина, оформление в 2–3 шага.
2. **Оплата**: Telegram Payments + Stars; чек в чат; статусы заказа с уведомлениями.
3. **Запись/бронирование**: слоты, напоминания за сутки/час, перенос в один тап.
4. **CRM**: карточка клиента, заметки, теги, история заказов, ответственный.
5. **Поддержка**: тикеты, передача оператору, ответы по шаблонам, ИИ-черновик ответа.
6. **База знаний + ИИ-ассистент**: ответы по FAQ и каталогу с источником; передача человеку при низкой уверенности.
7. **Business-режим Telegram** (`business_connection_id`): бот отвечает от имени аккаунта владельца, приветствие и «нет на месте».
8. **Аналитика**: воронка, выручка, конверсия, топ товаров, работа менеджеров (таблицы rich-сообщениями + график в мини-приложении).
9. **Рассылки и триггеры**: брошенная корзина, день рождения, «не покупал 30 дней».
10. **Отзывы и NPS**: после заказа — опрос, низкая оценка уходит менеджеру.

**Тон для бизнеса**: вежливо, коротко, на «вы»; без мата и шуток по умолчанию; эмодзи — только по делу (✅ 🧾 📦 💳 📅). Ошибка клиента — всегда следующий шаг («Не нашли заказ? Напишите номер, например 1042»).

**Чего не переносить**: игры, дуэли, РП, семья, «кто лох» — не для бизнеса. ИИ-режим «по-свойски» — выключить.

## 6. Готовый промпт для запуска проекта

> Создай Telegram-бота «Business Helper» на Python 3.12 + aiogram 3 + aiohttp, PostgreSQL (asyncpg) с запасным SQLite. Стиль — как у Chat Helper: команды обычными русскими словами без слэшей, ответы короткие, «эмодзи + жирный заголовок + курсивная подсказка», меню сеткой по 2 кнопки, цветные кнопки (success/danger/primary), опасные действия с подтверждением, ephemeral-ответы в группах, rich-таблицы для списков, мини-приложение для настроек и витрины, онбординг через /start. Роли: владелец, менеджер, оператор. Модули: каталог и заказы, оплата (Telegram Payments + Stars), запись с напоминаниями, CRM-карточки клиентов, тикеты поддержки с передачей оператору, ИИ-ассистент по базе знаний с передачей человеку, Telegram Business, сегментированные рассылки, аналитика воронки. Архитектура: роутеры по областям, middleware (метрики, блок-лист, трекер клиентов, антиспам), кэши с TTL, очередь записи в БД, webhook с постоянной очередью обновлений, подпись initData для Mini App, права проверять на сервере. Безопасность: параметризованный SQL, экранирование HTML, rate-limit, cap_drop/no-new-privileges в Docker, Caddy с HSTS. Все сторонние возможности (ИИ, rich, ephemeral) — «по возможности» с тихим откатом.
